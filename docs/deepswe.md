# Same-candidate DeepSWE evaluation: CLM vs Qwen3-8B letter logits

Fresh Jev 1.13.0 results on these same candidate trajectories are documented in [the Jev API report](jev_fresh_eval.md).

## Candidate set and inputs

The 38 task names are the previous CLM held-out list. Each task has the same
four public raw trajectories from
`kaitchup/DeepSWE1.1-trajectories-Qwen3.8-27B` (revision
`e58b83310346104971fd17c42f9955e7cd5e3b25`): Mini-SWE xhigh,
Claude Code xhigh, Pi medium, and Pi xhigh. The candidate trajectories were
generated by Qwen3.8-27B agents. They are **not** the Opus 5 candidates in
the prior CLM 31/38 reproduction.

Both selectors use `fair_inputs.jsonl`: the task request and the final 12
normalized agent action/observation turns of each candidate. Each action and
observation was clipped to 600 or 700 characters, with both its beginning and
end retained. The one trajectory ending in an execution error with no verifier
result was treated as failed. Verifier results were used for scoring only;
they were not included in model inputs.

**Correction, 2026-09-25:** The original CLM score below constructed each
state from only the earlier turns *within* the final-12 window. The official
DeepSWE evaluation takes the final 12 step scores, but each step's state may
contain the full preceding trajectory. We therefore reran CLM using all
available earlier normalized turns before the official 8K tail truncation.
That corrected approximate reconstruction selected 22/38, versus 21/38
for the window-only reconstruction. The original DeepSWE trace builder is not
released here, so neither reconstruction is an exact author-input reproduction.
See `clm_full_history_eval.py` and `clm_full_history_shard*.jsonl`.

## Fresh model computations

- **CLM:** Qwen3-8B revision `b968826d9c46dd6066d109eabc6255188de91218`
  recomputed last-token hidden states. For each of the 12 turns, the state is
  the task plus earlier turns within this window, encoded with the Qwen chat
  template and tail-truncated to 8,191 tokens. The current action is encoded
  as plain text, head-truncated to 8,191 tokens. The released DeepSWE
  `best_head.pt` projects normalized state/action vectors. We average the 12
  projected cosine scores and select the highest trajectory.
- **Qwen letter logits:** The same Qwen3-8B weights read all four candidates'
  normalized turns in one prompt and score A-D immediately after `Answer: `.
  Four cyclic orderings put every trajectory in each letter position once.
  Sum log probabilities by trajectory across the four orders and select the
  largest. Prompt lengths were 13,969-16,356 tokens. No reasoning text was
  generated.

The fresh evaluation ran four independent shards on four H100 GPUs. CLM
recomputed state and action encodings; it did not read the old parquet
embeddings. Qwen consumed 2,355,652 input tokens across 152 forward passes.
The longest shard's scoring loop took about 158 seconds, excluding model load
and preprocessing.

## Measured inference time

A repeat run on four H100 GPUs timed each method separately, synchronizing
CUDA before recording the boundary. Across all 38 tasks, CLM used 348.53 GPU
seconds (9.17 seconds/task) and Qwen letter logits used 250.40 GPU seconds
(6.59 seconds/task). Thus CLM took 1.39 times as long in this implementation.
The timings exclude model loading and input preparation. Each CLM task scores
48 state/action turns, requiring many short encoder forwards; each Qwen task
uses four long prompt forwards. The CLM path does not generate tokens. Timing
data is stored in the `timing` field of `fair_scores_shard*.jsonl`.
These CLM timings apply to the **window-only reconstruction**, not the
corrected full-history score. They use serial Transformers forwards, whereas
the released CLM inference path uses a vLLM pooling encoder, batching and
independent embedding caches. They do not measure the speed of the official
implementation.

## Results on exactly these candidates

| Selector | Successful picks / 38 | Mixed-outcome tasks / 21 |
| --- | ---: | ---: |
| CLM DeepSWE head, full available preceding history | **22** | **14** |
| CLM DeepSWE head, window-only state (earlier run) | 21 | 13 |
| Qwen3-8B balanced A-D logprob | **18** | **10** |
| Uniform random, expected | 19.25 | 11.25 |
| Best fixed agent configuration | 22 | 14 |
| Oracle | 29 | 21 |

The earlier CLM window-only run selected a success on five tasks where Qwen did
not; Qwen did so on two where that CLM run did not. The corrected full-history
run is four tasks ahead of Qwen, still too small to establish a reliable model
ranking on 38 tasks, and it ties the best fixed agent configuration.
The Qwen readout remained order-sensitive: the top letter was A in 97 of 152
prompts, and all four rotations selected the same trajectory on only 2/38
tasks.

## Limits

- The old Opus 5 candidate set had oracle 34/38; this new set has oracle
  29/38. Consequently, comparing the new 21/38 with the old 31/38 is invalid.
- The CLM head was trained on a different trajectory format. This experiment
  uses a documented normalization of Mini-SWE, Claude Code, and Pi logs rather
  than the unpublished original embedding recipe for these new runs.
- CLM scores actions sequentially with prior turns; Qwen judges completed
  excerpts together. They share the task, candidate trajectories, normalized
  evidence window, labels and outcome metric, but their computations differ.
- Truncating action/observation text can omit decisive code or test output.
  The result measures this bounded-context setup, not every possible way to
  score a full trajectory.

## Files

- `fair_inputs.jsonl`: exact shared normalized inputs and outcome labels.
- `fair_scores_shard*.jsonl`: fresh per-step CLM scores and per-order Qwen
  probabilities.
- `fair_results.jsonl` and `fair_summary.json`: merged selections and metrics.
- `fair_deepswe_eval.py` and `summarize_fair_deepswe.py` in the parent folder:
  preprocessing, model forward calls and aggregation.
